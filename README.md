# FATLOSS·CALC

Приложение из двух разделов на одном экране, переключение — через роутер,
без перезагрузки страницы:

| Вкладка | Что внутри |
|---|---|
| **Диета** | калькулятор нормы и БЖУ, шкала ИМТ, дневник веса с графиком, четыре варианта меню |
| **Активность** | интервальный таймер тренировок: фазы, шаблоны, свои таймеры |

На телефоне переключатель разделов находится **внизу экрана**, под большой
палец, а сверху остаётся только надпись `FATLOSS·CALC`. На планшете и десктопе
навигация — в обычной шапке.

Имена вкладок заданы в разметке (`index.html`). Внутренние имена модулей и
маршрутов остались техническими — `calc` и `timer`: они не видны пользователю,
а менять `#/timer` нельзя, потому что этот адрес уже опубликован.

**Демо:** https://westtrade.github.io/fatlosscalc/

## Запуск

Страница работает **полностью офлайн** — достаточно открыть `index.html`
двойным щелчком или отдать папку любым статическим сервером:

```bash
python3 -m http.server 8000     # затем http://localhost:8000
```

Интернет не нужен: все стили, скрипты и шрифты лежат в `assets/`.

## Структура

Код разделён на модули по разделам: стили и Alpine-приложения лежат рядом.

```
index.html                     только разметка (без <style> и <script>)

assets/common.style.css        общие стили: фон, «зерно», числа, тост, скроллбары
assets/calc/calc.style.css     стили калькулятора: ползунки, карточки, график
assets/timer/timer.style.css   стили таймера: drag-n-drop, анимации фаз

assets/common.app.js           оболочка: роутер, тост, сборка компонента
assets/calc/calc.app.js        калькулятор: расчёт, ИМТ, диеты, дневник веса
assets/timer/timer.app.js      таймер: фазы, шаблоны, звук, Wake Lock

assets/css/tailwind.css        собранный Tailwind (не тянуть из CDN!)
assets/css/fonts.css           @font-face для Manrope
assets/fonts/*.woff2           Manrope: 400/600/700/800, cyrillic + latin
assets/vendor/alpine.min.js    Alpine.js 3.17.4
assets/vendor/alpine-collapse.min.js   плагин Collapse (нужен для x-collapse)
assets/icons.svg               спрайт иконок: 28 <symbol id="i-…">
build-assets.sh                пересборка Tailwind, спрайта и вендорных файлов
tools/sync-sprite.py           встраивание спрайта в index.html
tools/split-monolith.py        разовая декомпозиция монолита (история)
agents.md                      правила работы с кодом (в т.ч. про иконки)
```

### Иконки

Все иконки — в спрайте `assets/icons.svg`, в разметке используются через
`<use href="#i-имя"/>`. Спрайт встраивается в `index.html` автоматически
(`./build-assets.sh`), потому что внешняя ссылка на `file://` не работает.
Как добавить иконку и почему презентация задаётся на `<svg>`, а не в `symbol`
— в `agents.md`.

### Как связаны модули

Три приложения регистрируют себя в `window.FLC` (`common`, `calc`, `timer`)
и объединяются в один Alpine-компонент `fatCalc` в `assets/common.app.js`:

```js
Alpine.data("fatCalc", () =>
  mergeModules(window.FLC.common(), window.FLC.calc(), window.FLC.timer()),
);
```

Два важных момента:

- **Скрипты подключены до `alpine.js`**, чтобы успеть подписаться на
  `alpine:init`.
- **Модули сливаются через дескрипторы, а не `Object.assign`.** `Object.assign`
  копирует значения и тем самым *вычисляет* геттеры — например `runningTimer`
  обращается к `this.timers`, которого в модуле оболочки нет, и падает.
  `mergeModules` переносит дескрипторы, сохраняя геттеры геттерами.

Используются классические скрипты, а не ES-модули: страница должна открываться
двойным щелчком с диска, а `import` на `file://` блокируется CORS.

### Куда добавлять новый код

| Что | Куда |
|---|---|
| Функциональность калькулятора | `assets/calc/calc.app.js` |
| Функциональность таймера | `assets/timer/timer.app.js` |
| Роутер, тост, общие хелперы | `assets/common.app.js` |
| Стили, нужные обоим разделам | `assets/common.style.css` |
| Стили только одного раздела | `assets/<раздел>/<раздел>.style.css` |

Если добавили Tailwind-классы в `index.html` — пересоберите CSS
(`./build-assets.sh`).

## Роутер

Переключение разделов — на хешах, состояние в `location.hash`:

| Маршрут | Вкладка |
|---|---|
| `#/` или пусто | Диета (`calc`) |
| `#/timer` | Активность (`timer`) |

Идентификаторы маршрутов (`calc`, `timer`) намеренно не переименованы в
`diet`/`activity`: `#/timer` уже разошёлся по ссылкам (в т.ч. редирект
`timer.html`), а смена хеша сломала бы их без пользы для пользователя.

```js
setRoute('timer')   // -> #/timer
setRoute('calc')    // -> #/
```

Важные детали:

- **Якоря разделов калькулятора не конфликтуют с роутером**: `#bmi`, `#tracker`,
  `#formula`, `#plan` — это обычные якоря, роутер реагирует только на `#/timer`.
  Поэтому прямые ссылки на разделы продолжают работать.
- При уходе с таймера на калькулятор таймер **не останавливается** — он
  продолжает идти, а его остаток виден бейджем в кнопке «Таймер». Блокировка
  прокрутки (`body overflow: hidden`) действует только пока открыт
  полноэкранный таймер: за это отвечает `syncBodyLock()`, подписанный на
  `activeId` и `route`.
- Горячие клавиши таймера (пробел, стрелки, `F`) работают только на его
  маршруте.

## Активность: интервальный таймер

Полноэкранный интервальный таймер (вкладка «Активность»): подготовка → работа/отдых × циклы →
пауза между сетами → успокоиться.

- Шаблоны: Дефолт, Tabata, HIIT, EMOM, Пилометрия.
- Свои таймеры: создание, переименование, дублирование, удаление с Undo,
  перетаскивание порядка.
- Звук (Web Audio) и вибрация по фазам, Wake Lock, чтобы экран не гас.
- Хранится в `localStorage` под ключом `itimer.timers.v2`.

Цвета фаз берутся из палитры проекта: подготовка — `sky`, работа — `acid`,
отдых — `ember`, между сетами — `rose`, успокоиться — `mint`.

## Пересборка ассетов

Раньше страница тянула Tailwind Play CDN, Alpine и шрифты из интернета.
Теперь всё локальное. Если вы **добавили новые Tailwind-классы** в
`index.html` (или поменяли цвета/шрифты), CSS нужно пересобрать — иначе
новые утилиты просто не будут иметь стилей:

```bash
./build-assets.sh
```

Скрипт скачивает Tailwind нужной версии, собирает `assets/css/tailwind.css`
по `index.html`, заново забирает шрифты и библиотеки. Требуется Node/npm и
интернет — но только на время сборки.

### Что важно знать при пересборке

- **Версия Tailwind должна оставаться 3.4.17** (`TAILWIND_VERSION` в скрипте).
  Именно она использовалась в Play CDN; на Tailwind 4 конфиг и часть классов
  несовместимы.
- **Тема задаётся в `build-assets.sh`**, в объекте `tailwind.config.js` внутри
  скрипта (цвета `ink`/`panel`/`acid`/`mint`/`ember`/`sky`/`rose`, шрифт
  `Manrope`, тени `glow`/`card`). При добавлении цветов в разметку добавьте их
  и туда.
- **`content` указывается абсолютными путями** — Tailwind резолвит их
  относительно текущего каталога, а не файла конфига; относительный путь даёт
  пустой CSS.
- **`content` перечисляет и `index.html`, и JS-модули в `assets/`.** Часть
  Tailwind-классов живёт в логике, а не в разметке: например `stroke-acid` и
  `fill-ember` задают цвета фаз таймера, `text-acid` — акценты в диетах. Если
  добавите новый файл с классами, допишите его в `content` внутри
  `build-assets.sh`, иначе утилиты не попадут в сборку и цвета сломаются.
- **Классы, которые собираются в рантайме склейкой строк**, Tailwind не найдёт
  никогда — держите имена целиком в коде (как в `phaseStroke`/`typeDot`).

## Замечание про x-collapse

В разметке есть `x-collapse.duration.350ms` (плавное раскрытие панелей
«Свой целевой вес» / «По ИМТ + рост»). Для этого нужен плагин Collapse —
он подключён в `assets/vendor/alpine-collapse.min.js` **до** `alpine.min.js`.
Без него Alpine выводит предупреждение и панели схлопываются без анимации.

## Меню («Практика» → «Как это съесть за день»)

Четыре готовых варианта диеты переключаются табами. Данные лежат в массиве
`diets` внутри компонента `fatCalc` в `index.html`.

Каждое блюдо описано так:

```js
{ name: "Завтрак", time: "07:30 – 09:00",
  kcal: 460, pro: 25, fat: 17, carb: 52, fib: 8,
  items: [
    { n: "Овсянка",     q: 70,  u: "г",  f: 1    },
    { n: "Молоко 2,5%", q: 150, u: "мл", f: 1    },
    { n: "Грецкий орех", q: 10, u: "г",  f: 0.1  },
  ] }
```

### Как пересчитываются порции

Калькулятор подгоняет меню под вашу норму калорий:

```
k = норма_калькулятора / базовая_калорийность_меню     (зажата в 0,7 … 1,5)
```

Каждый ингредиент масштабируется со своим коэффициентом эластичности `f`:

| `f` | Что это | Примеры |
|---|---|---|
| `1` | масштабируется полностью | крупы, мясо, рыба, молоко, овощи, фрукты |
| `0.3` | слабо | хлеб, авокадо, сухофрукты, соус, пита |
| `0.15` | почти фиксировано | масла, семена, оливки |
| `0.1` | фиксировано | орехи |

Для порции: `qty = q × (1 + (mult − 1) × f)`, где `mult` — множитель приёма.
Орехи при `f = 0.1` практически не меняются, крупы растут пропорционально.

Два важных правила:

1. **При `k = 1` меню совпадает с исходным до грамма.** Проверено тестом:
   все КБЖУ и клетчатка каждого приёма равны эталонным значениям.
2. После масштабирования множители приёмов **нормируются**, чтобы сумма за
   день точно равнялась норме калькулятора. Без этого «жёсткие» ингредиенты
   (орехи, масла) не добирали бы калории и итог расходился бы с целью.

Округление кухонное: штуки — целые, до 50 г — по грамму, крупные веса —
кратно 5 г.

### Если правило эластичности нужно изменить

Правьте поле `f` у конкретного ингредиента в `diets`. Значение `1` = «менять
пропорционально», `0` = «не менять никогда».

### Нормировка и клампы

- Норма выше базовой калорийности более чем в 1,5 раза → меню растёт до ×1,5
  и показывается предупреждение (добавьте приём пищи вручную).
- Норма ниже ×0,7 от базовой → меню урезается до ×0,7 с предупреждением.

## Сохранение данных

Всё хранится локально в `localStorage`, ничего не отправляется в сеть:

| Ключ | Содержимое |
|---|---|
| `fatlosscalc:input:v1` | текущий вес, цель, рост, режим, выбранная диета |
| `fatlosscalc:history:v1` | дневник веса: `[{ d: 'YYYY-MM-DD', w: Number }]` |
| `itimer.timers.v2` | список интервальных таймеров |

Кнопка «Сбросить» очищает параметры расчёта, но **не** удаляет дневник.
